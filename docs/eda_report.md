# Приложение: Отчет по Exploratory Data Analysis (EDA)

**Проект:** Guardrails Pre-filter для LLM-агентов

**Задача:** Подготовка данных для обучения классификатора (1 - attack, 0 - benign)

---

## 1. Концепция и стратегия данных

Данный датасет подготовлен специально для обучения LLM-агента, который служит фильтром безопасности.

* **Фокус на Hard Examples:** Основной упор сделан на примеры, где классические счетчики и простые ML-модели ошибаются.
* **Контрольная группа:** Сохранено 20% "простых" примеров для обеспечения адекватности оценки общей точности.

## 4. Краткая сводка выводов по EDA

* `MultinomialNB` сам по себе справляется довольно успешно с задачей разделения атак от доброкачественных промптов, однако сама вероятностная модель, помимо очевидной проблемы ограниченного словаря, отсуствует способность понимать сарказм, контекстную составляющую промпта, например role-play атаки.
* **Сложность задачи:** На графике **PCA** видно значительное смешивание классов в центре распределения. Это подтверждает, что простые "счетчики" не справятся с защитой, и использование LLM оправдано.
* **Состав выборки:** Для обучения извлечено 200 строк. Мы намеренно увеличили долю **Hard Examples** (до 80% от всего трейн датасета), так как обучение LLM на очевидных примерах (которые и так ловит `MultinomialNB`) экономически невыгодно. Итого в обучающей выборке 41% атак и 59% доброкачественных промптов. Для теста было взято 1000 строк, распределение по колонкам `compexity` X `label` сохранено эквивалентно трейну, для сохранения адекватности валидации.
* **Информативность:** Распределение длин слов (**Wordcount**) показывает, что атаки не имеют единого шаблона по длине, что делает их детектирование через простые эвристики затруднительным.
* **Итог:** Сформированный датасет является репрезентативным для "умного" пре-фильтра, так как заставляет модель фокусироваться на скрытых паттернах атак, а не на простых ключевых словах.
